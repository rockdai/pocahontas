# 多端连接库与凭据

方案更新：2026-11-03。Pocahontas 使用统一后台管理账号与密文存储，通过签名令牌支持多端登录；首期不做设备管理。iCloud 方案已取消；产品尚未发布，不做旧版兼容或数据迁移。

权威设计见 [Pocahontas 后台](../server/README.md)、[API 与加密协议](../server/protocol.md) 和 [PostgreSQL 数据模型](../server/schema.sql)。后台采用 Node.js、阿里云函数计算和 PostgreSQL，只引入必要的 `pg` 数据库驱动。

## 连接库原则

| 数据 | 本机 | 跨设备 |
| --- | --- | --- |
| 主机名称、地址、端口、用户名、分组 | 离线可用的账号隔离缓存 | 客户端加密后，经 Pocahontas 后台同步。 |
| 身份名称、公钥、指纹、凭据引用 | 与连接库共同管理 | 放在加密 payload 内，服务端不能按这些明文字段查询。 |
| SSH 密码与软件私钥 | 默认仅本机安全存储 | 用户逐项选择共享后，作为独立不可变凭据版本加密上传。 |
| passphrase | 当前解锁会话内存 | 首期不保存、不共享。 |
| 服务器 host-key 信任 | 本机 trust store | 不同步，新设备首次连接重新确认。 |
| 工作区名称、目录和 tmux 入口 | 配置，功能后续实现 | 可同步配置；不代表 SSH socket 或 agent 进程迁移。 |
| 终端输出、临时输入、剪贴板、SSH channel | 当前会话 | 不上传。 |
| 窗口、字号、键盘布局 | 设备设置 | 首期不跨设备覆盖。 |

Apple Keychain 仅用于本机安全存储，不启用 `kSecAttrSynchronizable`，不依赖 iCloud Keychain 或跨 App 的共享 access group。Android、鸿蒙分别适配本机安全存储，业务身份和同步格式保持一致。

客户端先可靠保存整份快照和待上传状态。server 保存当前整份密文，复用 app_user.updated_at 和单条条件 UPDATE 检查并发，不另设连接库编号、版本号或写入编号。密码变化后其他设备停止旧队列上传，重新登录并下载云端资料；旧的未同步编辑单独保留，提示用户手动处理，不能自动合并、重新加密或上传。没有增量日志、服务端历史记录、显式多语句事务或外键。客户端只在同一 passwordUpdatedAt 下自动三方合并，endpoint 与 authentication 作为一个冲突单元；删除标记保留在加密快照中。未知 schema 保留并标记只读，不能覆盖。

新设备输入邮箱和一个主密码，一次完成登录与密文库解锁。客户端从密码和 salt 按用途派生登录验证材料与 dataKey，直接用 dataKey 加密整份 SSH 资料；后台不接收主密码或解密密钥。不提供恢复密钥。注册必须验证邮箱；知道旧密码时生成新盐、重新加密完整资料并带来源快照的更新时间提交，保留内容；忘记密码时经邮箱验证与明确确认后生成新盐，用新密码派生的密钥加密空资料，替换旧云端密文。临时网络不可用不阻止使用已在本机解锁的资料。

## 实现状态

当前 App 代码仍包含 `CloudSync.swift`、CloudKit 账号逻辑、iCloud 设置与 entitlement，属于待删除实现，不再是产品方案。后台设计已明确替换清单；业务 API、客户端端到端加密与多端联调尚未实现。已有的本地存储、冲突合并、主机校验与 SSH 能力可以保留，不需要将旧 CloudKit 数据转入新库。
